# Banking Management System

A RESTful Banking Management System built using **Java, Spring Boot, Spring Data JPA, Hibernate, and MySQL**. This application provides APIs to create bank accounts, retrieve customer and account details, update account information, and delete customer accounts.

## Features

- **Create Account:** Register a new customer and create an associated bank account.
- **Retrieve Customer by Mobile Number:** Fetch customer and account details using a registered mobile number.
- **Retrieve Customer by ID:** Fetch customer and account details using the customer ID.
- **View All Customers:** Retrieve all registered customers along with their account details.
- **Update Account:** Update customer information and associated account details.
- **Delete Account:** Delete an account and its associated customer record.
- **Automatic Account Number Generation:** Generate a 10-digit account number when creating an account.
- **Input Validation:** Validate customer and account details using Jakarta Bean Validation.
- **Exception Handling:** Handle duplicate customers, missing resources, validation failures, and unexpected exceptions through a global exception handler.

### Layer Responsibilities

- **Controller:** Exposes REST endpoints and handles HTTP requests and responses.
- **Service:** Implements banking operations and business logic.
- **Repository:** Performs database operations using Spring Data JPA.
- **Entity:** Represents the customer and account database tables.
- **DTO:** Transfers customer and account data between the client and application.
- **Mapper:** Converts DTO objects into entity objects and vice versa.
- **Exceptions:** Handles application-specific exceptions and validation errors.
- **Constants:** Stores commonly used response messages and status codes.

## Database Design

**Database:** `bankmanagement_db`

The application uses two main tables.

### 1. Customer Table

| Column | Description |
|---|---|
| customer_id | Primary key, automatically generated |
| name | Customer name |
| email | Customer email address |
| mobile_number | Customer mobile number |

### 2. Accounts Table

| Column | Description |
|---|---|
| account_number | Primary key, automatically generated by the application |
| customer_id | Associated customer ID |
| account_type | Savings or Current |
| branch_address | Branch address |

The application associates account records with customers through the customer ID.

Hibernate automatically manages the database schema using the configured JPA DDL setting.

## API Documentation

**Base URL:** `http://localhost:8080/accounts/api`

### 1. Create Account

- **Method:** POST
- **Endpoint:** `/create`
- **Description:** Registers a new customer and creates a bank account.

**Request Body:**

```json
{
  "name": "Pavithra",
  "mobileNumber": "9876543210",
  "email": "pavithra@example.com",
  "accountsDto": {
    "accountType": "Savings",
    "branchAddress": "Chennai Main Branch"
  }
}
```

**Success Response:** `201 CREATED`

```json
{
  "statusCode": "201",
  "statusMessage": "Account created successfully"
}
```

### 2. Get Customer by Mobile Number

- **Method:** GET
- **Endpoint:** `/customer/{mobileNumber}`
- **Description:** Retrieves customer and account details using the registered mobile number.

**Example:**

```http
GET /accounts/api/customer/9876543210
```

**Success Response:** `200 OK`

```json
{
  "customerId": 1,
  "name": "Pavithra",
  "mobileNumber": "9876543210",
  "email": "pavithra@example.com",
  "accountsDto": {
    "customerId": 1,
    "accountNumber": 1234567890,
    "accountType": "Savings",
    "branchAddress": "Chennai Main Branch"
  }
}
```

### 3. Get All Customers

- **Method:** GET
- **Endpoint:** `/all`
- **Description:** Retrieves all registered customers along with their account details.

**Example:**

```http
GET /accounts/api/all
```

**Success Response:** `200 OK`

Returns a JSON array containing customer and account information.

### 4. Get Customer by ID

- **Method:** GET
- **Endpoint:** `/customer/id/{customerId}`
- **Description:** Retrieves customer and account details using the customer ID.

**Example:**

```http
GET /accounts/api/customer/id/1
```

**Success Response:** `200 OK`

Returns the matching customer and account details.

### 5. Update Account

- **Method:** PUT
- **Endpoint:** `/update`
- **Description:** Updates customer information and associated account details using the registered mobile number.

**Request Body:**

```json
{
  "name": "Pavithra",
  "mobileNumber": "9876543210",
  "email": "pavithra.updated@example.com",
  "accountsDto": {
    "accountType": "Current",
    "branchAddress": "Bangalore Main Branch"
  }
}
```

**Success Response:** `200 OK`

```text
Account updated successfully
```

### 6. Delete Account

- **Method:** DELETE
- **Endpoint:** `/delete/{mobileNumber}`
- **Description:** Deletes the account and associated customer record using the registered mobile number.

**Example:**

```http
DELETE /accounts/api/delete/9876543210
```

**Success Response:** `200 OK`

```text
Account deleted successfully
```

## Input Validation

The application uses Jakarta Bean Validation annotations to validate incoming customer and account details.

| Field | Validation |
|---|---|
| Name | Required; minimum 4 and maximum 20 characters |
| Mobile Number | Required; exactly 10 digits |
| Email | Required; must be a valid email address |
| Account Details | Required |
| Account Type | Required; must be Savings or Current |
| Branch Address | Required; minimum 2 and maximum 150 characters |

Invalid requests return HTTP `400 BAD REQUEST` with validation error messages.

## Exception Handling

A centralized exception handling mechanism is implemented using `@RestControllerAdvice`.

| Exception | HTTP Status | Description |
|---|---|---|
| CustomerAlreadyExistsException | 409 CONFLICT | Customer already registered with the given mobile number |
| ResourceNotFoundException | 404 NOT FOUND | Customer or account details not found |
| MethodArgumentNotValidException | 400 BAD REQUEST | Request validation failure |
| General Exception | 500 INTERNAL SERVER ERROR | Unexpected application errors |

## Configuration

### Prerequisites

Make sure the following are installed:

- Java 17 or a compatible newer JDK
- MySQL Server
- Maven (optional if using the included Maven Wrapper)
- IntelliJ IDEA or another Java IDE
- Postman for API testing

### 1. Clone the Repository

```bash
git clone YOUR_GITHUB_REPOSITORY_URL
```

### 2. Create the MySQL Database

Open MySQL and execute:

```sql
CREATE DATABASE bankmanagement_db;
```

### 3. Configure Database Credentials

Update `src/main/resources/application.properties` with your local database configuration.

```properties
spring.application.name=Mine

spring.datasource.url=${DB_URL:jdbc:mysql://localhost:3306/bankmanagement_db}
spring.datasource.username=${DB_USERNAME:root}
spring.datasource.password=${DB_PASSWORD}
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true

server.port=8080
```

Configure the following environment variables before running the application:

- `DB_URL` – MySQL JDBC connection URL.
- `DB_USERNAME` – MySQL username.
- `DB_PASSWORD` – MySQL password.

**Important:** Do not commit actual database credentials or passwords to GitHub.

### 4. Run the Application

Using the Maven Wrapper on Windows:

```bash
mvnw.cmd spring-boot:run
```

Alternatively, using Maven:

```bash
mvn spring-boot:run
```

Once the application starts successfully, the REST APIs will be available at:

```text
http://localhost:8080/accounts/api
```

## Testing the APIs

Use Postman to test the REST endpoints.

1. Start the Spring Boot application.
2. Open Postman.
3. Select the appropriate HTTP method.
4. Enter the endpoint URL.
5. For POST and PUT requests, select **Body → raw → JSON**.
6. Provide the request payload.
7. Send the request and verify the response and HTTP status code.
